# Agent

Agents consume bounded snapshot-bound material and produce exactly scoped proposals, Candidates, Check Outputs, research, or Implementation Worker reports. Decision, Change-scoped Planning, and aggregate Review Agents are Stage Producers. An Implementation Worker executes one accepted Work Unit through one exact Assignment and Candidate lineage in one Project Server-owned Workbench. Check executors judge exact subjects independently. Model Providers remain separate inference suppliers.

A DSH-backed Run runs through a DSH-based CodeWiki Run Process under complete CodeWiki custody of session inputs, tools, Pack Skills, queries, model route, budgets, cancellation, isolation, output, and receipt. A CodeWiki-launched Claude Code, Codex, ACP, or future delegate executes an exact task and Workbench under CodeWiki orchestration while retaining custody of any unobserved inner prompts, settings, tools, models, and Turn Loop. An independently operated Agent product connects as an External Agent Client through MCP; CodeWiki proves only the authenticated operations and admitted artifacts it observes. Product brand never upgrades one custody class into another.

A work-producing Agent may receive the exact optional Pack Skills for its current stage. Those Skills guide behavior through already admitted tools but cannot add authority, credentials, network, canonical writes, or lifecycle effects. Their complete digests bind the attempt and receipt. A delegated route is eligible only for Skills it can bind and receipt exactly. Code and Model Check executors receive no Pack Skills or producer memory.

Producer DSH-backed Runs query one locally mounted immutable Project Material Generation over exact WorkState, Knowledge, Alignment, repository, active Changes, accepted Work Graph, Evidence, and Results. A long-lived producer Session may adopt a newer generation only at a controlled idle boundary; every typed local query records its generation and bounds without a blocking Project Server round trip. Formal Checks receive a separate frozen Gate Evaluation Package and no producer query facade or memory. Every CodeWiki-controlled model-visible input and query is receipt-bound. Compaction rehydrates canonical facts rather than treating session memory or a persistent code heap as truth.

CodeWiki Agents never autonomously create, edit, install, update, or restore Check Packs or Runtime Plugins. A User may direct an External Agent Client to follow public Check and Agent Skill schemas and edit `.codewiki/check-packs/**` as ordinary project files; that Agent is the User's chosen editor, not a CodeWiki policy authority.

Agents cannot select Changes, alter canonical history, grant authority, schedule canonical descendants, choose Gate transitions, or perform guarded effects. When an Agent acts for a User through CodeWiki, exact delegation is required; otherwise it acts only as its own limited service Actor. Success means useful work resumes from canonical stage and operation identity rather than hidden conversation memory while custody, provenance, and semantic decisions remain independently inspectable.
