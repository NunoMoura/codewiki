# Automate Safe Work

As a maintainer, I want a standalone CodeWiki Backend to advance compatible work so routine progress survives browser, terminal, Agent Runner, or channel disconnection while unsafe progression remains blocked or explicitly stopped.

## Acceptance signals

- CodeWiki Backend owns durable Runtime, Server, Checks, WorkState, Workbench, and recovery responsibilities and starts exact pinned DSH Agent Runners through neutral Execution Ports.
- Server reconnects Clients to durable Runtime operations and canonical WorkState rather than private conversation state.
- Runtime creates exact Stage Producer attempts, selects and Claims Implementation work, isolates Workbenches, starts Backend Agent or Delegated Agent Runs, integrates admitted output, runs stage Gates, stops safely, and applies the fixed Decision → Planning → Implementation → Review lifecycle.
- Backend Agent Runs bind exact prompts, Skills, tools, routes, Stage Context, queries, budgets, compaction checkpoints, outputs, and raw session evidence. Delegated and External Agent Client receipts claim only facts CodeWiki actually controls or observes.
- Runtime reacts to admitted intent, Candidates, Gate outcomes, confirmations, scheduled reconciliation, and repository divergence; commits alone never imply stage progression.
- State-aware compaction retains exact execution history, rehydrates canonical facts, and summarizes only unresolved conversational state plus a recent tail.
- Review may be fully automated with independent Model and Code Checks; human Review Evidence is optional unless project Checks require it.
- Every accepted transition reaches accountability closure without requiring surveillance of incidental or inaccessible child-harness activity.
- Missing capability, stale state, external divergence, incomplete Evidence, Runner failure, or absent authority never silently relaxes policy or crashes the Backend.
