# Enforce Project Standards

As a maintainer, I want CodeWiki to apply accepted project expectations as bounded Checks so code, policy, design, and delivery requirements remain reviewable rather than hidden in agent prompts.

## Acceptance signals

- Default, imported, and Custom Checks remain open, inspectable, editable project files with explicit applicability, input, route, enforcement, and Repair Profiles.
- Every selected Check evaluates one exact Candidate and produces an independent Result, including indeterminate execution failures.
- Exit Reports explain required blockers, advisory and observed outcomes, and exclusions without hiding any selected Check.
- Model Checks are isolated and tool-free; code Checks run only in admitted sandboxes; neither has canonical Result authority.
- Assisted authoring is an explicit Client request routed through Managed Execution, shows exact validated diffs, and cannot silently promote enforcement or select the authoring model as evaluator.
- Repair context is Candidate-, report-, and Alignment-snapshot-bound, bounded, provenance-bearing, and grants no execution scope.
