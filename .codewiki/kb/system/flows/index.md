# Flows Knowledge Index

## Concepts

* [Change Lifecycle](change-lifecycle.md) - One Change carries accountable intent through immutable typed operations, exact Loop exits, rolling Planning, Implementation, Integration, delivery, outcomes, archive, and optional reopening.
* [Clean-Cut Audit](clean-cut-audit.md) - The pre-production cut replaces local-linear Trace and legacy Quality contracts with Change Trace Protocol v1, Git-synchronized acceptance, deterministic projections, and native Loop exit without migration or compatibility layers.
* [Decision to Planning Flow](decision-to-planning.md) - Planning consumes only an exact Decision Candidate whose Evidence-backed required Results produce a passing Exit Report and whose Runtime Route/disposition were accepted after final authority and freshness guards.
* [Planning to Implementation Flow](planning-to-implementation.md) - Passing atomic Planning epochs produce immutable worker-ready Work Items and Worker Workbench requirements; Runtime acquires exact Work Item Claims and Implementation accepts only candidate-bound integrated realization evidence.
* [Production Readiness Audit](production-readiness-audit.md) - CodeWiki remains private pre-production software; release requires Change Trace Protocol v1, Git-synchronized coordination, native exact Loop exit, deterministic Alignment Graph projection, archive/learning safety, and external proof.
* [Remote State Synchronization](remote-state-synchronization.md) - Runtime synchronizes accepted Change operations through provider-neutral Git expected-head CAS, treats local work as provisional, and rebuilds deterministic WorkState after stale, offline, or notification events.
* [Resume Context Boundary](resume-context-boundary.md) - Pi owns conversation/session compaction; CodeWiki resumes semantic project work from accepted Change operations, fresh WorkState, Knowledge, source/Git, policy, archive, and exact recovery refs rather than private cognition.
* [Runtime Work Item Claim Flow](runtime-work-item-claims.md) - Passed Planning yields worker-ready Work Items; Runtime provisions exact Worker Workbenches, acquires Work Item Claims, supervises isolated Assignments, and feeds Worker Report evidence into exact integrated Implementation assurance.
